#### Nhận diện cái dạng bài có thể áp dụng được dynamic programming
**dynamic programming** thường áp dụng cho các dạng bài optimization (tìm giá trị min max). Bài giải cho dynamic programing thường bao hàm nhiều step. Ở mỗi step, chúng ta sẽ có một danh sách các lựa chọn cố định. Việc cần làm là tính toán độ hiệu quả của từng lựa chọn và lấy lựa chọn tốt nhất.

 **dynamic programming** chỉ khả thi khi đáp ứng hai điều kiện sau đây:
1. **Optimal substructure:** bài toán có lời giải tổng quát bao hàm optimal solution của một hay nhiều subproblem. Để tìm lời giải tối ưu, chúng ta thường phải chọn subproblem cho ra kết quả tốt nhất. Ngoài ra, số lượng lựa chọn phải cố định hoặc có ít để thuật toán phát huy hiệu quả.
	
2.  **overlapping subproblems:**  Một điều kiện qua trong khác là phải có sự lặp lại (overlapping) subproblems. Sự lặp lại này là cơ sở cho kỹ thuật caching lưu giữ kết quả của các subproblem để tận dụng cho lần tiếp theo. 

Bài toán [Min Cost Climbing Stairs](https://leetcode.com/problems/min-cost-climbing-stairs/description/): 
cho một array `Cost[n]` gồm `n` phần tử trong đó mỗi phần tử biểu thị cost cho mỗi bậc thang. Mỗi lần chỉ được bước một hoặc hai bậc thang. Tìm min cost để bước hết cầu thang trên.

 $F(x)$ hàm hồi quy tìm min cost cho hành trình đến được bậc thang số $x$ như sau:
$$
F(x) = min(F(x-1), F(x-2)) + Cost(x)
$$
Bài toán trên áp dụng được **dynamic programing** do đáp ứng cả hai điều kiện nêu lên ở trên:
- Lời giải có **Optimal substructure** ở chỗ là mỗi step là sự lựa chọn giữa hai kết quả từ hai subproblem nhỏ hơn đó là $F(x-1)$ và $F(x-2)$. 
- Nếu ta tăng giá trí $x$ lên, ta có thể thấy các subproblem đã có kết quả trước đó sẽ được tái sử dụng lại cho bài toán có $x$ lớn hơn. 
#### Độ hiệu quả của thuật toán dynamic programing
**Dynamic programming** không thực sự phải là một giải pháp tối ưu mà là một kiểu vét cạn (brute force) đi hết các trường hợp khả dĩ để tìm kiếm kết quả tốt nhất. Tuy nhiên **dynamic programing** tỏ ra hiệu quả hơn so với phương pháp vét cạn thông thường, do không cần phải tính toán lại cho các subproblem trước đó mà tận dụng kết quả đã lưu trong cached. 
#### Cách triển khai thuật toán dynamic programing

Bước đầu tiên cần làm là phải xác định được công thức hồi quy (**incursion**) phù hợp với dynamic programing. Sau đó, dynamic programming có thể triển khai theo một trong hai cách sau đây.
##### bottom-up approach
Phương pháp **bottom-up** tính toán kết quả cho các **subproblem** theo chiều từ giá tri thấp nhất đến giá trị mong muốn.  Phương pháp này thường áp dụng cho bài toán có lựa chọn dùng đơn vị nhỏ nhất. Ví dụ như bài toán [Min Cost Climbing Stairs](https://leetcode.com/problems/min-cost-climbing-stairs/description/) khi mỗi bước giải ta có thể bước lên một bậc.

Do khoảng cách giữa các subproblem lân cận chỉ có một, thường solution sẽ đi qua tất cả các subproblem có thể có. 

``` python
def find_min_climbing_cost_bottom_up(cost_table: list[int]):
    max_step = len(cost_table) - 1
    stored_value: list[int] = [0, cost_table[0]]
    current_step = 2

    while current_step <= max_step:
        result: int = (
            min([stored_value[current_step - 1], stored_value[current_step - 2]])
            + cost_table[current_step]
        )
        stored_value.append(result)
        current_step += 1

    return stored_value[max_step]
    
if __name__ == "__main__":
    cost_table = [2, 3, 5, 0, 3, 4, 4, 1]
    min_cost_by_bottom_up = calculate_minimum_climbing_cost_bottom_up(cost_table)
    print(min_cost_by_bottom_up) # 7
```
##### top-down approach
Một phương pháp khác đó là áp dụng **top-down**. Lúc này ta dựa vào công thức hồi quy để xây dựng giải thuật hồi quy (**recursion**). Tuy nhiên khác với giải thuật recursion thông thường, hàm hồi quy sẽ có logic kiểm tra giá trí đã tính toán và lưu cho cached trước đó chưa.
**top-down** sử dụng tabular data structure như dictionary hoặc key-value table để lưu giữ kết quả cho các subproblem.

```python
def find_min_climbing_cost_top_down(cost_table: list[int]):
    max_step = len(cost_table) - 1
    stored_value: dict[int, int] = {0: 0, 1: cost_table[0]}

    def find_min_cost(target: int) -> int:
        if target in stored_value:
            return stored_value[target]
            
        result = (
            min([find_min_cost(target - 1), find_min_cost(target - 2)])
            + cost_table[target]
        )
        return result

    return find_min_cost(max_step)
```

#### Xác định phương pháp tối ưu
Thông thường các bài toàn áp dụng dynamic programming cho ta kết quả tối ưu. Dựa vào cached và áp dụng back-tracing ta thế xây dưng sequence các step để ra kết quả đó. 

Bài toàn phụ xác định các bước để hoàn thiện sau khi xong bài toàn tìm gia trị tối ưu.
sử dụng  kỹ thuật back-tracing theo chiều top-down. Sử dụng các giá trị trong cached table để tìm đến kết quả tối nhất.

``` python

def find_optimal_steps_for_climbing_stair(cost_table: list[int]) -> list[int]:
    # construct table for storing output of every subproblem.
    max_step = len(cost_table) - 1
    stored_value: list[int] = [0, cost_table[0]]
    current_step = 2

    while current_step <= max_step:
        result: int = (
            min([stored_value[current_step - 1], stored_value[current_step - 2]])
            + cost_table[current_step]
        )
        stored_value.append(result)
        current_step += 1

    # base on stored table, using back-tracing technique to acquire the optimal steps (top-down orientation)

    steps: list[int] = []
    current_step = max_step
    
    while current_step >= 0:
        steps.append(current_step)
        best_step, _ = min(
            [
                (current_step - 1, stored_value[current_step - 1]),
                (current_step - 2, stored_value[current_step - 2]),
            ],
            key=lambda entry: entry[1],
        )
        current_step = best_step

    return steps
```
