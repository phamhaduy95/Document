### Introduction

S3 là serverless storage cho phép quản lý và lưu trữ các object, cho phép user upload và download file thông qua cơ chế HTTPS/HTTP.
S3 đảm bảo durability của S3 object lên đến 99.999999999% (11 con số 9).
S3 là region specific resource tức một region sẽ quản lý một S3 riêng.
S3 tạo backup cho mỗi S3 object ở tối thiếu ba AZ khác nhau trong 1 regions.

Các ứng dụng phổ biến của AWS S3 bao gồm:

- Lưu trữ các file log từ các service khác của AWS.
- Lưu trữ các backup data từ RDS hay AIM cho IC2 instance.
- Hosting static websites.
- File server.
- Data lake cho các ứng dụng big data và data analyst.

#### S3 Bucket

AWS S3 quản lý các file trong các S3 bucket. Mỗi bucket sẽ có một global unique ID trong toàn hệ thống S3 toàn cầu của AWS. (Câu hỏi nên đặt tên như thế nào).

Khi sử dụng S3 sẽ có nhưng restriction cần lưu ý như sau:

- Mỗi một account chỉ được phép tạo tối đa 100 bucket và file size không vượt quá 5TiB.
- upload/download file không được lớn hơn 5GiB, cần partition file thành các phần nhỏ hơn có kích thức tối đa 100MB thông qua tính năng **Multipart Upload**

#### S3 prefix

S3 bucket là flat storage không hỗ trợ cấu trúc phân tầng hierarchy structure.
Tuy nhiên, ta vẫn có thể gom nhiều object trong 1 group quản lý chung bằng thêm prefix vào id của object

 **Randomize Amazon S3 key name prefixes**
- Amazon S3 automatically partitions objects by key name to achieve parallelism and scalability.
    
- If your object keys follow a **predictable pattern** (e.g., sequential prefixes like `user1/...`, `user2/...`), it can cause **hot partitions** — leading to throttled performance.
    
- To achieve **better request distribution**, randomize key prefixes (e.g., prepend a random hash or timestamp).

Instead of: images/001.jpg, images/002.jpg
Use:        a9f-images/001.jpg, b3d-images/002.jpg

#### S3 Classes

Tùy vào access frequency và pricing, AWS cung cấp 1 catalog chủng loại (classes) cho S3 như sau
**Standard**
- **Amazon S3 Standard (S3 Standard)**
	- đảm bảo  99.99% availability, availability SLA là 99.9%.  
	
**High performance**: premium tier với performance vượt trội.
- **Amazon S3 Express One Zone**
	- hỗ trợ bandwidth lớn, tốc độ truy cập cao, độ trễ thấp (X10 so với S3 standard).
	- bị hạn chế  bị giới hạn trong 1 AZ để đảm báo tốc độ truy cập cao.
	- Phù hợp cho các ứng dụng big data, data analyst, ML.
	- No life cycle support.
	
**Archiver** : cost thấp, giới hạn truy cập vài lần trong năm.
- **Amazon S3 Glacier Instant Retrieval**
	- tần xuất truy cập cho phép 1 lần 1 quý.
	- tốc độ truy cập nhanh ngang với S3 standard.
	- thích hợp archive data cần truy cấp nhanh.
- **Amazon S3 Glacier Flexible Retrieval (Formerly S3 Glacier)**
	  - đảm bảo  99.99% availability và availability SLA là 99.9%.
	  - hạn chế số lần access 2 lần 1 năm
	  - Retrieval time in minutes
	  - Ideal for backup and disaster recovery use cases when large sets of data occasionally need to be retrieved in minutes, without concern for costs
- **Amazon S3 Glacier Deep Archive**
 	- Đảm bảo 99.99% availability, availability SLA là 99.9%.
 	- Retrieval time within 12 hours
 	- Hạn chế số lần access 2 lần 1 năm

**S3 Intelligent-Tiering:** Cung cấp giải pháp tự đông di chuyển các object xuống các tier Infrequent Access tier khi các object không được truy cập trong hơn 30 ngày và xuống tiếp Archive tier sau 90 ngày. AWS sẽ charge thêm phí quản lý tự động cho tier này.

#### S3 object life cycle

Để tiết kiệm tri phí lưu trữ S3, ta có thể tạo một policy tự động di chuyển các object từ class có chi phí cao xuống class có chỉ phi thấp.

#### Logging S3 activities with CloudTrail

Ta có thể log event thay đổi status cũng như các action thực hiện trên từng S3 object thông qua CloudTrail.  Các event log từ S3 thuộc dạng data-event.
Mặc đinh, data-event cho S3 object bị disabled để tránh sinh ra quá nhiều các event CloudTrail.

#### pre-signed URL

Ta có thể tạo một **URL** tạm thời cho phép truy cập, thay đổi và download 1 object nằm trong 1 S3 bucket mà không yêu cầu authentication. Pre-signed URL có thời gian hiệu lực là 3600s (tầm 1h). User có thể điều chỉnh lại expiration time.

##### Object Versioning

Để tránh trường hợp data corruption hoặc xóa nhầm S3 object, ta có thể bật tính năng versioning cho S3 bucket. Lúc này mỗi một lệnh PUT hoặc DELETE vào object, S3 sẽ tạo ra 1 version cho từng thay đổi của object đó. User có thể download về các version cũ hơn trong trường hợp cần thiết.

Ta có thể tạo lifecycle management rule cho các object version như số lượng các version tối đa và retention time cho các version.

#### S3 Eventual consistency

Do S3 bucket sao lưu object tại 3 AZ khác nhau. Nên khi thực hiện các lệnh PUT và DELETE, S3 phải cần 1 khoảng thời gian đủ lâu để sync data cho toàn bộ các backup. Chính vì thế, khi user muốn download 1 object vừa được thay đổi, sẽ có trường hợp object được trả về chưa được cập nhật thay đổi.
Với object được tạo mới, S3 đảm bảo strong consistency, data trả về luôn mới nhất.

#### S3 High Availability

S3 đảm bảo tính high availability thông qua các yêu tố sau đây:

- sao lưu object ở nhiều AZ khác nhau.
- multi-region replication: cho phép tạo sao lưu tại các region khác giúp giảm thiểu latency tại mỗi region và backup khi có sự cố

#### S3 configuration

Noticeable S3 configuration:

- **AWS Region**: The region where the Amazon S3 bucket is created.
- **Object replication**: Automatically replicate objects to other Amazon S3 buckets hosted in the same region (Same Region Replication) or other Amazon S3 regions (Cross Region Replication) to help with disaster recovery. Replication can also be to another AWS account
- **S3 bucket policy**
- **S3 Block Public Access** - Block Public Access settings are enabled at the bucket level
- **S3 Access Points**
- **Object lock**: Enable write-once/read-many (WORM) policies on objects or buckets to manage compliance requirements. Define a “retain until date” or “legal hold” protection.
- **S3 Transfer acceleration** Speed up the transfer of larger Amazon S3 objects over long distances from the end user to the S3 bucket using CloudFront global edge locations and the AWS private network for uploads and downloads
- **Multi-Region access point**
- AWS PrivateLink for Amazon S3: tạo 1 gateway VPC endpoint
- **event notifications** can be sent in response to actions in Amazon S3 like PUTs, POSTs, COPYs, or DELETEs
- **Server access logging** provides detailed records for the requests that are made to a bucket. Each access log record provides details about a single access request, such as the requester, bucket name, request time, request action, response status, and an error code

#### Access Control

User có thể thiết lập policy quản lý access cho 1 bucket theo 2 phương thức:

- **IAM policy**: attach vào IAM user hay IAM role.
- **S3 bucket policy**: là `resource-base policy` liên hệ trực tiếp với S3 bucket, có syntax giống với IAM policy nhưng có thêm field `principal`quy định các thực thể **(identity)** nào được sử dụng S3 bucket đó.
- **Access Control List**: không khuyến khích bởi AWS


#### Object lock policies
Amazon S3 buckets and Amazon S3 Glacier have data policies that can lock objects so they **cannot be deleted or changed**. Amazon S3 objects can be locked using a **write-once/read-many** (`WORM`) policy.

**retention period**: number of days or years during which an object will remain locked, protected, and unable to be overwritten or deleted. There 2 two retention modes:

- **Governance mode**: An S3 object cannot have its lock settings overwritten and cannot itself be overwritten or deleted unless the user has unique permissions.
- **Compliance mode**: A protected object in your AWS account cannot be overwritten or deleted by anyone, including the root user, for the entire retention period.

**legal hold**: lock one single object or entire bucket without expired date. You can alter or remove objects unless the locking is lifted.

#### S3 Transfer Acceleration 

S3 Transfer Acceleration leverages Amazon CloudFront's globally distributed edge locations to optimize long-distance data transfers. Instead of uploading directly to the destination S3 bucket, data is routed through the nearest edge location, which then transfers the data over the AWS backbone network.
